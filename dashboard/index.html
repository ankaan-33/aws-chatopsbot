ChatOpsBot

AWS alerts and operations, straight into Slack. This page is the team's read-only reference for how the alert path works and what can be run from the channel.

Dashboard served from a private S3 bucket through CloudFront (Origin Access Control)
EC2 CPU spike→ CloudWatch alarm→ SNS topic→ Amazon Q Developer→ Slack channel + email

Check what's firing

@Amazon Q cloudwatch describe-alarms --state-value ALARM --region <region>

Get a status summary

@Amazon Q lambda invoke --function-name chatopsbot-ops-status --region <region>

Guardrails

Channel permissions are capped at read-only access plus invoking the ops function. Nothing destructive can be run from chat.

Simulate an incident

Open the test instance in Session Manager and run stress-ng --cpu 2 --timeout 300. The alert lands in Slack within ~2 minutes.
